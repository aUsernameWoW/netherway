# 验收清单：服务器短码

- [ ] **短码真机直连**
  - 内容：服主在 `netherway.cfg` 的 `server` 类目配置 `S:shortCode=open sesame 42`（`runAgent=true`），玩家在多人游戏添加服务器、地址栏填 `nw-open sesame 42`。
  - 操作说明：
    1. 在一台有公网/可打洞环境的机器上启动安装了 Netherway 的服务端，确认日志出现“短码已启用”与 `[serve:shortcode]` 的 serve-ready 日志。
    2. 在另一个网络（如手机热点）的客户端添加服务器，地址填 `nw-open sesame 42`（再用 `NW-OPEN SESAME 42` 试一次大小写）。
    3. 等待几秒，观察服务器列表该条目的延迟，点击进入。
  - 预期效果：该条目显示延迟（不是“无法连接”），点击后进入服务器；`netherway` 日志显示隧道 READY；服务端日志看到连接来自回环（或 PROXY 真实地址）。
  - 用户反馈：
- [ ] **弱短码告警**
  - 内容：`S:shortCode=abc` 启动服务端。
  - 操作说明：查看服务端启动日志。
  - 预期效果：出现“server.shortCode 不足 8 个字符”告警，服务仍正常启动。
  - 用户反馈：
- [ ] **原凭证机制不受影响**
  - 内容：同时配置短码与默认会合点凭证，用 1.12.2/1.7.10 客户端按原方式（预取 / 登录下发）连接。
  - 操作说明：不填 `nw-` 条目，直接添加服务器真实地址进入。
  - 预期效果：照常预热并升级为 P2P 直连，与未配置短码时一致。
  - 用户反馈：
- [ ] **经短码进服后不会多起一条升级隧道**
  - 内容：玩家经 `nw-<短码>` 隧道进服后，服务端仍会按原流程（预认证 / 登录）下发主 serve 的凭证；它的会话密钥与短码派生值不同，需确认不会额外起一条升级隧道或在两条隧道之间来回切换。
  - 操作说明：完成「短码真机直连」后在服务器里停留 2 分钟，然后查看客户端 `.minecraft/netherway` 下的 agent 日志和游戏日志。
  - 预期效果：游戏一直不掉线；日志里要么没有新的升级 agent，要么升级完成后连接平稳，没有反复重连。若出现第二条隧道，记录日志反馈给我。
